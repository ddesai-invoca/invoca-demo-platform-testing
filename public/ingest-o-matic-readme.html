Demo Call Ingest-O-Matic

How this module works

Keeps Invoca's demo networks (Telecom/1847, Healthcare/2160) stocked with synthetic call history — on a schedule, or on request — and keeps a running log of what got sent, what failed, and what it cost.

The short version

A parent orchestrator (plain server logic) decides when and what date range. For every actual send, it hands the job to a real Claude agent scoped to one network's folder, which follows that network's own AGENT_PROMPT.md — dry-run, a 3-call test batch, then a full send, escalating on the error codes its prompt says to escalate on. The orchestrator never talks to Invoca's API directly; the agent does, using its own Bash tool to run that folder's Python scripts, exactly as a human operator would.

Adjusting the schedule

One setting governs both networks. When it fires, it dispatches the same date range to both Telecom and Healthcare.

CadenceFiresRequests
Monthly1st of the month, 1amThe full previous calendar month
Biweekly1st and 15th, 1amThe previous half-month
Weekly1st, 8th, 22nd, 28th, 1amThe preceding ~7 days
DailyEvery night, midnightThe previous calendar day

Add calls (ad-hoc requests)

Pick one network, a start date, and an end date, then submit. Two rules are enforced on the server, not just the form:

  • The end date can't be in the future.
  • The start date can't be more than 2 years before today.

Test mode (checked by default) tells the agent to run its dry-run and 3-call test batch, then stop — it never does a full send. Uncheck it only once you're confident the request is right; a full send can consume real, unique call IDs from that network's content bank and cannot be undone.

The ingestion log & error report

Every request — scheduled or ad-hoc — gets one row: date, network, calls ingested, errors, credits used (the real Anthropic API cost of the agent run that handled it), and who asked for it (a real signed-in admin, or Mr. Roboto for a scheduled run). The Errors panel breaks failures down by cause, with a plain-English explanation and a recommended fix for each — written by the agent that actually hit the error — and can be downloaded as a text report.

Where things live

  • agents/subagents/telecom-1847/ and agents/subagents/healthcare-2160/ — each network's AGENT_PROMPT.md, ingestion scripts, and content bank (template_calls.csv), committed to this repo.
  • Each folder's network_config.env (API credentials) and state/ (the permanent send-history ledger — never reuses a call ID) are not in git. Credentials are written from server environment variables at boot; state lives on the persistent disk so it survives redeploys.
  • Ingestion run records and the schedule setting live alongside the rest of this app's data (one JSON file per run), the same way saved demos do.
A full send is real. It consumes fresh, permanently-unique call IDs and posts real data to Invoca's Call Ingestion API for that network. There's no "undo" — only "add more with different IDs." When in doubt, use test mode first.
